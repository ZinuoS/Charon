## What the freeze requires

See the checklist in `preregistration/README.md`. `tests/test_preregistration.py`
enforces both directions automatically: while `frozen_at` is null it asserts the
author-owned fields are *still* TODO (so an analysis session cannot quietly fill one
in), and the moment `frozen_at` is set it flips to asserting that no TODO survives and
every status reads `frozen`.

## Known blockers carried into the freeze

Each hypothesis carries a `known_blockers` list. Summarising: H1, H2 and H4 all depend
on data with **no confirmed public source** as of S1 — KRX single-stock
futures/options, the USDKRW NDF curve, KOSPI200 futures settlement series, and the SKHY
and 000660 option surfaces. See `docs/data_sources.md`.

This does not prevent the freeze — a pre-registration is a statement of what you claim,
not of what you have already measured — but the resolution dates should be set with the
sourcing risk in view, since a hypothesis whose data never materialises resolves as
"untestable," which is itself a legitimate recorded outcome.
