## M1 (README §6)

`pipeline/measurement/premium.py` · `asynchrony.py` · `comparators.py`, plus 27 tests.

**Both measurement choices are config axes, not defaults.** Sessions 5–6 measured two
effects of the same kind — analyst choices whose magnitude sits on the order of the daily
phenomena being studied:

| Choice | Effect | Basis |
|---|---|---|
| Close definition | **24.6bp** | consolidated tape vs. primary official close, 2026-07-28 |
| FX fix instant (levels) | 5bp mean / **51bp p95** | ECB vs FRED H.10, 2,850 days |
| FX fix instant (**changes**) | **26.6bp mean / 70.6bp p95** | same pair, 2,849 changes |

Burying either in a default would put a noise floor into π that nobody could decompose
afterwards. Every variant is computed where inputs exist, stored side by side, and each
artifact records both axis choices.

**Ratio-awareness.** `compute_premium` accepts a date-indexed ratio series and
forward-fills it (correct for a ratio, which persists until the depositary changes it;
wrong for a price, which does not). A test fixture halves the ratio and the ADR price
together — economically nothing happens — and asserts ratio-aware π stays flat while
naive π shows a spurious ~50% jump. That is the S3 Task 2.1 hazard, caught before S3.

**Comparators share the code path literally.** `comparators.compute_premium is
premium.compute_premium` is asserted. README §8 makes D6 the training universe and SKHY a
forward test, which is only valid if both are measured identically — this makes it a fact
rather than an intention.

## Findings

**The decomposition identity is exact.** Written in logs,
`Δln(1+π) = Δln P_adr + Δln FX − Δln P_local`, all three terms observable, nothing
estimated. On 2,327 days of real TSM data the maximum residual is **0.00e+00**.

**TSM attribution** (2,327 days): mean |Δln(1+π)| = 162bp; ADR leg 161bp, local leg
130bp, FX leg 21bp.

**⚠️ The FX-instant artifact is larger on changes than on levels, and it matters.**
Differencing two independently-noisy fixes *amplifies* rather than cancels: the level gap
is 5bp mean, but the day-over-day **change** gap is **26.6bp mean / 70.6bp p95**. Against
TSM's 162bp typical daily premium change, that is **~16% of a typical day's move**
attributable purely to which FX clock you read.

This is the strongest argument yet for the ECOS 15:30 KST fix (`731Y003.0000003`), which
is contemporaneous with the KRX close and would collapse the reducible component toward
zero. It is also why `asynchrony.py` quotes the change-basis figure: the decomposition
operates on changes, so the level-basis number would understate the artifact by ~5×.

# Session 7 addendum

## Correction to a number I reported in this file

S2 above quotes the FX-fix level gap as "5bp mean". That is the **signed** mean — a
systematic +5.5bp bias of the ECB fix over the noon-New-York fix. It is **not** the
typical magnitude, which is the absolute mean, **19.0bp**. Both are true and they answer
different questions; quoting the signed figure where a reader expects "how big is this
usually" understates it by ~3.5×.

Corrected table:

| Statistic | Level gap | Change gap |
|---|---|---|
| signed mean (bias) | +5.5bp | ~0 |
| **mean abs (typical size)** | **19.0bp** | **26.6bp** |
| p95 abs | 51.1bp | 70.6bp |

The conclusion is unchanged and slightly strengthened: against TSM's 162bp typical daily
premium move, the change-basis artifact is ~16% of a typical day.

# ⚠️ D5 first pull — the flagged empirical question is answered

`docs/data_sources.md` recorded an open question that "cannot be settled from
documentation and is decided only by the first post-2026-07-29 observations": does KSD's
`DR전환가능주식수량` track the **foreign-ownership limit**, the **2.5% deal cap**, or the
tighter of the two?

**Answer: neither company-level constraint. The field is PROGRAM-SPECIFIC.**

The first pull found **two** SK Hynix DR programs, behaving completely differently:

| ISIN | Rows | Range | Latest headroom |
|---|---|---|---|
| **US78392B2060** | **1** | 2026-07-15 only | **0** |
| US78392B1070 | 1,260 | 2010-03-31 → 2026-07-28 | 129,711,611 |

**The decisive observation is that one company has two different numbers.** A
foreign-ownership limit is a property of the *issuer*, so an FOL-driven field would show
one shared figure. It does not. The field therefore tracks each **program's own issuance
ceiling minus its DRs outstanding**.

**US78392B2060 reads exactly zero, with a single observation dated 2026-07-15** — five
days after the SKHY listing. That is the 2.5% deal cap, exhausted at the offering exactly
as README §2 states, and it is the barrier-state variable README §3.3 wanted: it reads
*sealed*, and it is the first direct observation of the upper barrier this project has.

**US78392B1070 is a legacy program** (history to 2010) and is **moving**:

```
2026-07-14  129,669,963
2026-07-15  129,669,986      (+23)
2026-07-16  129,671,183   (+1,197)
2026-07-20  129,686,021  (+14,838)
2026-07-21  129,711,021  (+25,000)
2026-07-28  129,711,611     (+590)
```

Headroom **rising** = DRs being cancelled = capacity freed. Total +41,648 shares over the
window — **0.03% of the program**, so this is a trickle, not a flow that could compress a
22% premium.

## What this means for H5, stated carefully

Three things are now established, and one is not:

1. **[V] The observable exists and is free, daily, per-ISIN, back to 2010.**
2. **[V] The correct series for the SKHY barrier is US78392B2060**, not the legacy
   program. Building H5 on US78392B1070 would measure a different, unconstrained channel
   and produce a confident wrong answer.
3. **[V] The deal-cap program's headroom is 0** and has produced one observation in two
   weeks.

4. **[U] Whether US78392B2060 will produce a usable daily series at all.** One row in two
   weeks may mean KSD only publishes on change, or that the program genuinely has not
   moved. **If headroom stays pinned at 0 and KSD publishes only on change, H5's
   independent variable is a constant** — and a call written against "headroom creation
   precedes premium compression" would be untestable, not refuted. That distinction
   belongs in the resolution criterion, and the `minimal_freeze_checklist.md` already
   flags it as the one question to settle before writing H5's threshold.
