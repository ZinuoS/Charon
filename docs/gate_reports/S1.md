ordinary retry. These are correct going forward but could not undo the existing block.

- Affects both `query1` and `query2` hosts.
- Affects `curl` and Python `requests` identically, so it is **not** a TLS-fingerprint

- **Flaps.** One watcher observed a clean `200`, but the pull launched immediately after

**This is recorded as a probable permanent loss.** Free providers retain 1-minute bars

built around — the earnings-morning asynchrony decomposition, where the local leg traded

at **daily** resolution instead of intraday.

That materially weakens F3 but does not invalidate it: the decomposition identity holds
at daily resolution, it just cannot show the intra-session path. Documented here rather
than worked around, per README §8 ("a documented gap beats a silently degraded series").

**Decision for the author:** whether to source the intraday window from a paid or
credentialed provider before it ages out, or accept the daily-resolution version of F3.

## Provider fragility layer (new standing constraint)

`pipeline/ingest/_http.py` now holds every network concern, and it is the **only**
networked module in the repo — enforced by `test_ingest_is_the_only_networked_package`.
`_yahoo.py` was refactored from a transport into a thin **adapter** that owns only the
payload→column-contract mapping.

Five rules, each with tests (`tests/test_fragility.py`, 21 tests):

| Rule | Implementation |
|---|---|
| Exponential backoff **with full jitter** | `_backoff()`; jitter is asserted, because deterministic backoff across symbols re-synchronises into a burst and re-trips the limit the instant it lifts |
| **Single-flight per host** | per-host lock; a concurrency test asserts max 1 in-flight request to one host across 8 threads |
| **Resumability** | `write_immutable` makes an already-persisted symbol a free no-op, so an interrupted panel pull resumes rather than restarts |
| **Local response cache** | content-addressed on URL+params; asserted to prevent the second network call |
| **No pacing to assumed quotas** | reacts to observed 429/503 only. FRED's "120/min" and ECOS's "10,000/day" are absent from both providers' documentation |

Backoff jitter is seeded (`random.Random(20260728)`) so the retry path stays reproducible
under README §8 — unseeded jitter would make a retry-path failure irreproducible exactly
when reproducing it matters.

## Snapshot harness (Task 0.2) — built, gated, not run

`pipeline/ingest/snapshot_daily.py` persists one dated, append-only raw capture per run
for sources whose history may not be retrievable: **D4** Naver ETF NAV/AUM and **D5**
KSD/SEIBro DR capacity. The raw response is stored verbatim and parsed downstream, so a
parser bug can never destroy an unrepeatable capture.

It currently reports both as `BLOCKED / approval=pending` and exits without touching the
network. **Approval is the only remaining step.**

### Scheduling: use launchd, not cron

On macOS, **cron does not survive sleep** — a laptop closed at the scheduled minute
simply skips the day, which is precisely the failure a perishable-capture harness exists
to prevent. `launchd` with `StartCalendarInterval` runs the job on wake if the window was
missed.

Write `~/Library/LaunchAgents/com.charon.snapshot.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.charon.snapshot</string>
  <key>WorkingDirectory</key><string><repo-root></string>
  <key>ProgramArguments</key>
  <array>
    <string>uv</string>
    <string>run</string><string>python</string><string>-m</string>
    <string>pipeline.ingest.snapshot_daily</string>
  </array>
  <key>StartCalendarInterval</key><dict><key>Hour</key><integer>19</integer><key>Minute</key><integer>0</integer></dict>
  <key>StandardOutPath</key><string><repo-root>/data/derived/snapshot.log</string>
  <key>StandardErrorPath</key><string><repo-root>/data/derived/snapshot.err</string>
</dict></plist>
```

Then load it:

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.charon.snapshot.plist && launchctl kickstart -p gui/$(id -u)/com.charon.snapshot
```

19:00 local is chosen so the capture lands after the KRX close (15:30 KST) plus the
after-hours session — **TODO(ash): confirm, and confirm the NAV strike time**, since a
snapshot taken before NAV is struck captures the prior day's value under today's date,
which is a look-ahead error in the opposite direction.
