# Session 15 — Cap 0: D4 issuer capture RETRACTED, and a self-corrected misread

**Both KODEX and TIGER issuer pages are JS SPAs carrying no fund data in static HTML.**
Marked `ABSENT_UNRESOLVED` in `snapshot_daily.py`; neither is captured any longer.

**A correction to the record.** Session 14's commit `6acd199` claimed the KODEX capture
"carries a NAV token, an embedded timestamp and large integers" as evidence it was not an
empty shell. That was wrong, and I found it by parsing the stored bytes rather than
trusting the earlier claim:

- `253039467` → a **Google Analytics ID** (`UA-253039467-1`), not a fund figure
- `20260728070300` → a build timestamp
- `하이닉스` → inside a marketing blurb ("AI반도체 TOP2…")
- `NAV` → a JavaScript label string
- The data-bearing check (`순자산총액` / `기준가격`, the actual Korean AUM/NAV labels) → **False**

The lesson is the same one the figure audit surfaced: a claim drifts toward what the
author wanted to see unless something checks it against the actual bytes. "Verified not an
empty shell" was true (136KB) and irrelevant (136KB of marketing JS).

**Consequence for H3 — stated plainly.** H3's rebalance-notional estimator needs issuer
AUM. **There is now no landed AUM input at all:**

- The terms-clean issuer routes (KODEX, TIGER) do not yield AUM via static capture — they
  need a browser to run the SPA and capture its XHR, or the JSON endpoint identified.
- The one D4 route *verified* to carry AUM (the Naver `etfItemList.nhn` JSON, which an
  earlier research probe confirmed returns NAV and market cap for the single-stock 2×
  products) is **withheld on terms** — restrictive and unreviewed.

So H3 is not "single-issuer instead of two-issuer." **H3 is data-blocked** until either a
browser-capable capture is built for the issuer SPAs, or the author rules on the Naver
terms question. That is the honest status, and the power analysis in Block 3 is moot until
an AUM series exists.
