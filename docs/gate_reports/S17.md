# S17 gate report — extending the local-projection horizon

**Stage:** S17, item 1 of the S16 preview.
**Intent as written:** *"Extend the local projection horizon past h=20 so the half-life is
interpolated, not extrapolated — this single change unlocks sheets' cost stacks and sizing."*
**Outcome:** the extension worked and **the premise behind it was wrong.** The crossing is now
observed, and observing it removed the point estimate rather than supplying one.

---

## What was expected, and what happened

The S16 gate withheld all horizon-dependent economics because the 227-day half-life came from
extrapolating ρ_h ≈ exp(−h/τ) eleven times past a 20-day fitting window. The fix looked
mechanical: fit further out, watch ρ cross ½, read off the horizon, unlock the cost stacks.

Fitting to h=400 on the same 2,328-observation constrained pair:

| | Result |
|---|---|
| First passage of ρ below ½ | **h ≈ 331** — in-window, no longer extrapolated |
| The old extrapolated figure | 227d — **too fast by ~46%** |
| Independent spans at the crossing | **~6** (2,028 overlapping rows ÷ 331) |
| t-HAC at the crossing | 1.74 — **not significant** |
| Lower 95% band crosses ½ at | **h ≈ 143**, t-HAC 5.95, ~15 spans — identified |
| Upper 95% band crosses ½ at | **never, at any estimable horizon** |

Two findings, and the second is the one that matters.

**The extrapolation was biased toward optimism.** It projected convergence 46% faster than the
data show. Every cost computed off it would have been understated, and understated in the
direction that makes the trade look better.

**There is no finite upper bound on the half-life.** The upper edge of the 95% HAC band stays
above ½ across the entire window where coefficients can be estimated at all. These data do not
reject a premium that never halves. That is not a precision problem to be fixed with more
horizons — it is the answer.

## What this does to the S16 gate

It does not unlock a point estimate. It replaces `pending M3 estimate` with something a desk
can actually quote:

> Financed cost accrues over **at least 143 trading days (~7 months)** at 95%, **with no upper
> bound.**

Cost is linear in holding period. A floor with an open tail is quotable; a point estimate off
an unidentified crossing would have been the same fabrication S16 refused to commit, arrived
at by a longer route. `sizing_horizon()` now returns the floor, the point, and
`holding_period_ceiling_days = None` — where `None` means *unbounded*, not *missing*, and a
test pins that distinction.

**The binding risk this exposes:** a financing line that can be withdrawn inside seven months
is short the position's own horizon. That is now the first thing the live sheet says about
holding this trade, and it was invisible while the horizon was a single extrapolated number.

## Method changes (`pipeline/convergence/jorda.py`)

- `MAX_HORIZON` 20 → 400, on a **sparse-long/dense-short grid** — 10-day steps past h=110,
  because the crossing interval is hundreds of days wide and finer steps buy no resolution.
- **`n_eff = n/h` reported on every fit.** Overlapping windows mean 2,028 rows at h=331 carry
  ~6 independent spans; the row count is not the evidence count, and reading a standard error
  against n rather than n_eff is how the old figure looked sturdier than it was.
- Horizon window **capped at `n_eff ≥ 5`**. Past that ρ_h stops being monotone — it wanders and
  turns back up (ρ rises to 0.41 at h=750), which is overlap artefact, not re-divergence.
- Half-life is a **`HalfLife` interval** with a `support` classification: `interpolated` /
  `interpolated_underpowered` / `extrapolated` / `sub_resolution`. The constrained regime is
  `interpolated_underpowered` — crossing observed, location not pinned.
- **First-passage rule**, not "the" crossing, because a non-monotone path can cross repeatedly
  and first passage is the only rule that needs no choice among them.

### A bug the extension exposed

The fungible control has ρ₁ = 0.038 — **already below ½ at the shortest horizon.** With no
crossing to find, it fell through to the exponential branch and printed *"ρ does not decay —
no finite half-life."* That phrasing means *never converges*; the truth is that it converges
faster than one trading day can resolve. The control and the constrained pair would have
printed nearly the same words for opposite reasons. Fixed with an explicit `sub_resolution`
branch and a regression test named for the failure.

## Verification

- 28 tests in `tests/test_jorda.py`, 25 of them new, pinning semantics rather than numbers:
  n_eff arithmetic, the cap, first-passage-not-last, unbounded-upper, the underpowered/
  identified distinction, and the sub-resolution regression.
- 3 tests in `tests/test_hedging.py` **rewritten, not deleted** — they had encoded the S16
  state (`== PENDING_M3`). They now assert the stronger invariant: horizon fields must read as
  a bound, must declare the open tail, and must not derive a point cost from the unidentified
  crossing.
- `g_convergence` redrawn: 95% bands shaded, markers only where ≥12 spans support the fit, the
  floor and first passage annotated. Its old caption asserted ρ *never* crosses ½ — false after
  this change, and a stale caption on a correct chart is worse than no chart.
- Full suite green. `01_client_note` (5 figures) and `05_hypothesis_engines` (2) re-executed
  clean; both carry the revised finding in prose.

## Standing

`support = interpolated_underpowered` and `provisional = True` both hold: the regime taxonomy
is still unratified and the constrained class still holds one pair. The floor is the claim.
