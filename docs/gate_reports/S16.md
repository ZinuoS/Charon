## Block 0 — the path taken, and why

The S16 prompt gated trade economics on the M3 metrics table. The table exists and is
populated. **I did not treat that as sufficient**, and this is the substantive judgement of
the session.

What M3 actually delivers, and how firmly:

| Quantity | Value | Standing |
|---|---|---|
| ρ₁, one-way-constrained regime | 0.9387 | t-HAC **128.98**, n = 2,327 — robust |
| ρ₁, fungible control (BABA) | 0.0400 | insignificant, n = 1,593 — robust |
| Implied half-life | **227 days** | **extrapolated 11× beyond a 20-day fitting window, from a single pair, PROVISIONAL taxonomy** |

The persistence *contrast* is the finding, and it is solid. The half-life is not — it is a
projection off a local-projection horizon that stops at h=20. And the asymmetry matters
directionally: **financing cost scales linearly in holding horizon.** Publishing a financed
cost off an extrapolated 227-day horizon does not produce an uncertain number, it produces a
fabricated one, in a document whose whole claim to usefulness is that it does not fabricate.

So: **structure everywhere, horizon-dependent economics nowhere.** Every field that requires
a convergence horizon renders the literal token `pending M3 estimate`, and §6 of the client
note carries a table naming which future estimate fills each cell. A reader can see the shape
of the trade and see precisely what is missing from it.

## Block 1 — hedging construction (`pipeline/hedging/ratios.py`)

**The derived result worth reporting:** a premium position is **not FX-neutral even when the
local leg is fully FX-hedged.** The premium is itself a currency-exposed notional — the excess
of ADR notional over local notional — and it is exactly the part a local-leg hedge does not
reach.

```
ADR leg                     $130.17
local leg (USD equivalent)  $106.20
RESIDUAL premium notional    $23.97   = 18.4% of the ADR leg
```

`identity_check` returns exactly `-0.0`, confirming residual/ADR = π/(1+π) analytically.

**Then I tested it, and had to correct my own claim.** I first wrote that the analytic
sensitivity was "confirmed on 2,300+ real observations." It is not. Regressing daily premium
changes on daily FX changes gives a slope of **0.805**, not 1.0, with correlation 0.109. The
correction, now encoded as module constants:

- `FX_COEF_EMPIRICAL = 0.805`, `FX_COEF_CI95 = (0.507, 1.103)` — theory sits inside the
  interval, so it is not rejected, but it is imprecisely pinned.
- Diagnosis: both equity legs carry strong negative FX betas (−1.91 ADR, −1.69 local) that
  partly offset the mechanical channel.
- `FX_R2_ALONE = 0.012` — **FX explains ~1.2% of daily premium variance.** Hedging the
  currency removes a real but secondary risk; it does not make this a low-variance position.

That caveat is printed in the client note verbatim, not buried in a docstring.

`beta_hedge()` and `sizing_horizon()` return `PENDING_M3` by construction — they cannot be
made to emit a number without the M5 context layer and the half-life respectively.
